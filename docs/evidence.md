## Concrete acceptance results

- Startup validates receiver configuration and reserves its listener before database access. A real-process PostgreSQL regression first reproduced tenant provisioning by a deployment that then rejected its incomplete webhook settings. The corrected executable leaves tenant state unchanged on configuration or port failures. Three non-database startup cases and two actual PostgreSQL cases also prove WorkOS-only boot without API keys, mixed-provider tenant provisioning, isolated service identities, persisted work and exact replay across process restarts, and rejection of removed service keys. These process checks use synthetic configuration and do not contact WorkOS.
- A blocked signing-key refresh no longer stalls valid operators whose keys are still fresh. The regression reproduced 20 stalled operator HTTP requests before the fix; afterward they complete while 20 new-key requests share the held provider fetch. Additional cases prove expired keys cannot bypass an ongoing rotation, failed/cancelled refreshes retain rate limits, removed keys are rejected and the cache recovers after provider restoration.
- Optional WorkOS AuthKit is implemented with explicit server-side organization/role maps and verified RS256 access tokens. Twelve non-database Rust cases, one actual PostgreSQL signed-token case and nine browser cases passed. These prove local cryptographic/identity guards, persistent actor isolation, PKCE/session behavior and recovery across refresh, expiry, identity switches and stalled token acquisition. No real WorkOS project is enabled or qualified by these fixtures; see [activation and revocation bounds](authentication.md).
- Changing a generic webhook receiver after an attempted delivery makes no HTTP request to the replacement, including after audited requeue. Restoring the original endpoint permits exact-event recovery with a rotated credential. The regression first reproduced the unsafe redirect. Migration 008 upgrades the actual preceding seven-migration schema, retains prior outcomes and marks unknown historical recipients for review. - Eleven malformed, mismatched or forbidden save-recovery responses now run as independently timed browser cases with unchanged assertions. An earlier aggregate run hit its shared 60-second test budget; the focused eleven-case repeat passed. Browser case counts reflect this split, not ten new product behaviors.
- A command lost before arrival remains recoverable under its original ID. ## Persistence and integration boundaries

Current stock, products, locations, receipt lines, orders and allocation ownership use normalized PostgreSQL rows. Database triggers independently enforce physical movement, reservation and exact receipt-line balances. Movement/activity histories are append-only and paginated. Operational reads include active work, bounded completed work and bounded recent history. The former 8 MiB warehouse JSON aggregate limit is removed; writes still serialize within a warehouse. State, archived details and order/receipt history reconstruct line/allocation children from normalized rows even if cached JSON child types are malformed. The [workload report](performance.md) retains baseline, intermediate and final active-work measurements; the prior larger Store profile passed on a fresh disposable PostgreSQL cluster.

The [native integration report](native-integrations.md) identifies the actual Sync and Freight routes, authentication, response envelopes and unresolved contract gaps. Sync remains the commercial order authority; WMS owns physical inventory; Freight creates and executes transportation plans. Source-derived contract tests do not establish deployed credentials or the two applications' tenant mappings.

Native OMS writeback defaults to held because the legacy upstream endpoint lacks conditional revision and terminal-state fences. An additive [companion receiver patch](../integrations/stateset-sync-server/README.md) supplies the atomic predicate, exact source-line proof and immutable success/rejection receipts. It is compiled and tested against actual upstream types but remains unapplied and undeployed in the sibling OMS. Opt-in WMS `conditional_v1` mode requires that deployed receiver and verified tenant capabilities; it never falls back to the legacy endpoint. Native Freight import creates a planned load; it does not establish carrier acceptance, pickup or delivery. Generic warehouse event webhooks remain a separate producer contract requiring compatible consumers.
